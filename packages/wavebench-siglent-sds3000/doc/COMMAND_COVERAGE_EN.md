# SDS3000 Manual Command Coverage Baseline

[中文](COMMAND_COVERAGE.md)

## Conclusion

The February 2026 manual explicitly documents 578 entities: 478 callable entities and 100 Automation objects. Every entity has a unique stable ID, source page, direction, safety class, WaveBench mapping, and disposition. The unclassified count is zero.

The complete machine-readable catalog is [`command-catalog.json`](command-catalog.json), generated by [`../tools/manual_catalog.py`](../tools/manual_catalog.py). It records identifiers and audit metadata only; vendor descriptions, examples, and response prose are not copied.

Automation objects remain in the catalog because they establish namespaces and model or option applicability. Additional CVARs that the manual mentions but does not enumerate are outside the denominator.

## Current dispositions

Starting with M4, catalog schema v2 adds `direction_dispositions` to each legacy command. It tracks command and query directions separately so implemented `WF?` reads cannot be mistaken for `WF` write-back support, and implemented `*OPC?` cannot be mistaken for `*OPC` command support.

The current M6 dispositions are 16 `implemented`, 2 `partially-implemented`, 8 `core-gap-rfc`, 340 `firmware-unverified`, 78 `option-absent`, 2 `model-not-applicable`, 132 `unsafe-quarantined`, and zero `planned` entities.

The following M1 figures are the historical denominator-freeze snapshot rather than the current implementation state.

At the M1 boundary, the catalog contains 20 `planned`, 10 `core-gap-rfc`, 336 `firmware-unverified`, 78 `option-absent`, 2 `model-not-applicable`, and 132 `unsafe-quarantined` entities. No entity claims `implemented` during the denominator-freeze milestone.

“100% coverage” means that every explicit entity must ultimately have reproducible implementation or disposition evidence. It does not mean executing every instruction. Option-specific, model-inapplicable, and dangerous instructions remain covered without being run on hardware merely to improve a percentage.

## Manual anomalies

All 164 Part 7 index rows are cataloged. `DD_PES_SETUP` (`DPSU`) appears in both indexes but has no command body heading. Its catalog entry carries `body-heading-not-present` and records both command and query directions from the explicit index semantics.

A small number of index and body titles differ in a question mark, star, or short-form spelling, including index token `3DB` versus body token `D3D`. These entries carry `index-body-token-mismatch`; the extractor does not silently rewrite vendor identifiers.

## Safety boundary

Factory reset, panel save or recall, calibration, self-test, filesystem, email, printing, external-device, date, network, option activation, shutdown, and arbitrary VBS operations are excluded from automated hardware tests. Operations with uncertain restoration or read-to-clear semantics are also quarantined.

A typed capability may use a fixed, reviewed vendor command sequence internally. Neither the plugin nor WaveBench may expose arbitrary SCPI or VBS execution.

## Reproduction gate

With all three ignored local manual segments available, run from the package directory:

```bash
python tools/manual_catalog.py --check
pytest tests/test_manual_catalog.py
```

The tests freeze the 578/478 totals, all per-kind counts, 164 Part 7 rows, unique stable IDs, callable directions, legal dispositions, absence of copied vendor prose, and byte-for-byte regeneration. CI still validates the committed catalog when vendor material is absent; only local regeneration is skipped.
