# SP3000A RS-232 只读协议验收

[English](RS232_READONLY_ACCEPTANCE_EN.md)

## 结论

一台已开机的 SP3000 系列设备完成了首轮 M2 只读探测。当前 RS-232 链路在 `9600 baud / 8N1 / 无流控 / LF` 下可稳定执行身份查询和一组核心状态查询，但手册中的若干候选查询在目标固件上无响应或返回未文档化的 `Error`。因此本轮结论是**标量只读协议部分通过，曲线查询未获准执行，M2 尚未完整关闭**。

本轮没有发送设置、触发、输出、复位、保存/调出或返回本地命令；没有修改 RF、扫频、显示、marker、检波或保存槽。真实串口资源和任何实验室专用日志均未进入公开记录。

## 会话与 framing

- 打开已确认的目标资源后，发送查询前的被动监听为静默状态。
- `*IDN?` 连续 5/5 返回完全一致的 38 字节 ASCII 行。
- 身份响应只声明 `SHENGPU SP3000 Series Digital Sweeper`，没有给出可独立确认的 SP30120A 子型号或固件版本。
- 响应以单个 LF (`0x0A`) 结束，没有 CR、命令回显或额外 ACK。
- 一条完整身份响应可能分成多次底层 `read()` 返回，因此 transport 必须累计到已验证的终止符，不能把一次 `read()` 当作一条响应。
- 身份查询约 100 ms 完成；成功的短状态查询通常约 50–100 ms 完成。该观察只用于首版超时设计，不能视为所有状态和固件的完成时间保证。
- 成功查询结束后继续被动监听 1 秒，没有收到迟到响应或异步数据。

## 安全裁决

- 由于 `OUTPRFORM:CONT?` 无响应，无法证明曲线连续上传已经关闭。
- 由于设备原本 `RFSTAT=ON`，且本阶段禁止改变 RF，本轮不尝试任何 acquisition-format 写入。
- 因上述两个条件，`OUTPRFORM?` 被主动跳过；没有曲线帧、点数、单位或频率轴通过实机确认。
- 不尝试长短命令拼写变体，不重试失败查询，不用 `SYSTem:LOCal` 自动改变会话状态。
- 未文档化的精确字符串 `Error` 必须作为设备私有确定性失败处理，不能当作正常值，也不能自动重试。
- 当前成功查询集合可作为 M3 query-only 驱动的首批候选；无响应和 `Error` 查询在确认正确固件命令前必须保持 unsupported。

## M2 剩余退出门槛

M2 完整关闭前仍需：

1. 由操作员确认 RMT 后可通过面板 `Shift/Local` 恢复本地控制；
2. 找到并验证目标固件实际支持的曲线连续上传、模式和点数查询；
3. 在能够证明连续上传为 OFF 后，再批准一次有读取上限的 `OUTPRFORM?`；
4. 确认子型号和选件信息的独立证据，不从系列 IDN 推断 SP30120A；
5. 保持 M4 的曲线格式写入与 parser 验证独立于本阶段。

在这些门槛完成前，公开状态应写为“RS-232 标量只读协议部分验证”，不能写成“SP30120A 驱动或曲线采集已通过”。
