# SP3000A RS-232 只读协议验收

[English](RS232_READONLY_ACCEPTANCE_EN.md)

## 结论

一台已开机的 SP3000 系列设备完成了首轮 M2 只读探测。当前 RS-232 链路在 `9600 baud / 8N1 / 无流控 / LF` 下可稳定执行身份查询和一组核心状态查询，但手册中的若干候选查询在目标固件上无响应或返回未文档化的 `Error`。因此本轮结论是**标量只读协议部分通过，曲线查询未获准执行，M2 尚未完整关闭**。

首轮只读矩阵没有发送设置、触发、输出、复位、保存/调出或返回本地命令。后续获得明确授权后，仅补做了两个手册内受控写入：发送 `OUTPRFORM:CONT OFF` 以尝试关闭连续曲线上传，再发送 `SYSTem:LOCal` 以尝试交回面板。两条命令均无手册预期确认，且没有改变 RF、扫频参数、显示、marker、检波或保存槽。真实串口资源和任何实验室专用日志均未进入公开记录。

## 会话与 framing

- 打开已确认的目标资源后，发送查询前的被动监听为静默状态。
- `*IDN?` 连续 5/5 返回完全一致的 38 字节 ASCII 行。
- 身份响应只声明 `SHENGPU SP3000 Series Digital Sweeper`，没有给出可独立确认的 SP30120 子型号或固件版本。实机由操作员和外观信息确定为 SP30120；不能从该系列 IDN 推导手册中的 SP30120A。
- 响应以单个 LF (`0x0A`) 结束，没有 CR、命令回显或额外 ACK。
- 一条完整身份响应可能分成多次底层 `read()` 返回，因此 transport 必须累计到已验证的终止符，不能把一次 `read()` 当作一条响应。
- 身份查询约 100 ms 完成；成功的短状态查询通常约 50–100 ms 完成。该观察只用于首版超时设计，不能视为所有状态和固件的完成时间保证。
- 成功查询结束后继续被动监听 1 秒，没有收到迟到响应或异步数据。

## M3 驱动路径验收

可安装的 `wavebench-shengpu-sp3000a` 0.1.0 已通过一次端到端实机只读验收。通过 WaveBench 核心 serial transport 打开目标资源后，插件的 `idn()` 成功确认已验证的 SP3000 系列身份，`read_scalar_status()` 成功读取并解析上述全部稳定标量字段。

该路径只发送 `*IDN?` 与固定 allowlist 中的状态 query；未调用 transport 写接口，未发送曲线、配置、触发、RF、保存/调出或 Local 命令。descriptor 导入、entry point 发现与 registry 加载仍为零仪器 I/O。验收只证明 query-only M3 驱动和标量解析，不扩张 M2 的曲线与本地状态结论。

## 安全裁决

- `OUTPRFORM:CONT?` 无响应；随后受控发送 `OUTPRFORM:CONT OFF` 也未返回 `OK` 或其它确认，因此无法证明曲线连续上传已经关闭。
- 由于设备原本 `RFSTAT=ON`，且本阶段禁止改变 RF，本轮不尝试任何 acquisition-format 写入。
- 因上述两个条件，`OUTPRFORM?` 被主动跳过；没有曲线帧、点数、单位或频率轴通过实机确认。
- 不尝试长短命令拼写变体，不重试失败查询。受控收尾发送 `SYSTem:LOCal` 后未收到手册预期的 `LOC`，因此也不能证明远控状态已恢复。
- 未文档化的精确字符串 `Error` 必须作为设备私有确定性失败处理，不能当作正常值，也不能自动重试。
- 当前成功查询集合可作为 M3 query-only 驱动的首批候选；无响应和 `Error` 查询在确认正确固件命令前必须保持 unsupported。

## M2 剩余退出门槛

M2 完整关闭前仍需：

1. 由操作员确认 RMT 后可通过面板 `Shift/Local` 恢复本地控制；串口 `SYSTem:LOCal` 当前无 `LOC` 证据；
2. 找到并验证目标固件实际支持的曲线连续上传、模式和点数查询；
3. 在能够证明连续上传为 OFF 后，再批准一次有读取上限的 `OUTPRFORM?`；
4. 保留 SP30120 型号的操作员/外观证据并独立确认选件；不从系列 IDN 推断 SP30120A；
5. 保持 M4 的曲线格式写入与 parser 验证独立于本阶段。

在这些门槛完成前，公开状态应写为“SP30120 RS-232 标量只读协议部分验证”，不能写成“曲线采集已通过”或把实机冒认为 SP30120A。

## 后续曲线探索的时间线边界

上述“主动跳过 `OUTPRFORM?`”准确描述的是首轮 M2 只读会话。后续在单独授权的探索会话中曾执行有限曲线查询和返回模式写入，但没有形成可验收的 M4 结论：

- 一次基线读取只得到 739 个数值，响应没有已确认的 LF 结束边界，并出现明显的后段零值；该响应只能视为不完整或失步帧。
- 后续多次读取稳定得到 1002 个数值并以 LF 结束，其中前 501 个为有限非零候选值，后 501 个全部为零。
- 标记为 AMPT、PHASE 和 ALL 的三组实验都呈现相同的 501+501 结构，因此不能证明返回模式写入已经生效，也不能判断零值半段代表关闭的相位测量、无效数据还是旧流残留。
- 写入连续上传、返回模式或 RF 状态命令附近曾读到曲线样式数据而非可识别 ACK，说明当时的会话可能存在控制响应与异步曲线流混流。

这些结果是后续 M4 的私有协议证据，不覆盖首轮 M2 的历史记录，也不构成曲线 parser、点数、单位、状态恢复或 `sweep_analyzer.trace` capability 的验收。M4 必须从静默会话边界重新确认 `CONT OFF`，再按预期 token 数和 LF 双重条件验证 AMPT、PHASE、ALL 以及至少两种点数。
